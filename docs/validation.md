## 已修复的关键问题

- 模型可能忽略原问题条件：先独立识别日期、指标、工具、条数和不支持条件，再核对计划；不执行被静默缩小的查询。
- 金额和图形：Decimal保留四位，飞书显示两位；网页图形用编码区分同名对象，飞书图形使用独立序号；零基数和无订单均值不伪造0。
- 网络与持久化：调用模型前保存中断标记并移除原文；未知调用不重试。飞书明确拒绝记`rejected`，不确定送达记`unknown`，不自动重复发送。
- 飞书授权重载移到领取回复前，避免配置短暂不可读时搁置`ready`任务。
- 追问按当前消息入队时间和同身份／同快照判断30分钟有效期；清除按请求顺序生效，避免排队或发送顺序导致错误继承。
- 原连接测试曾收到飞书业务码`99991672`，检查`im:message:send_as_bot`权限和应用版本生效后，新消息回复成功；旧不确定状态未批量重置。

## 复现命令

默认后端验证不联网、不读写数据库，从`backend/`执行：

```powershell
../.venv/Scripts/python.exe -m pytest -q -p no:cacheprovider
../.venv/Scripts/ruff.exe check . --no-cache
```

数据库和模型测试须分别显式开启：`ERP_RUN_INTEGRATION=1`只读恢复后的源库；`ERP_RUN_ASSISTANT_TESTS=1`只写独立助手库的合成任务并清理自身记录；`ERP_RUN_MODEL_TESTS=1`发送合成问题但不发送业务结果。具体命令见[飞书问数](feishu-analytics.md)。不要在默认回归中开启全部外部调用。

从`frontend/`执行`npm run build`，设置`PLAYWRIGHT_CHANNEL=chrome`后执行`npm run test:e2e`；测试服务使用合成快照和8765端口。飞书本地预览复现见[展示说明](feishu-analytics.md)。
