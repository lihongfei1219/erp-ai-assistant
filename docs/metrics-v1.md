# 首批指标定义 v1

版本：`qy.sales_orders.v1`。状态：可执行的订单数据核对口径，待业务确认后才能升级为正式经营口径。

数据所有者已确认原备份覆盖平台全部商家。本阶段以 `XSDDH/XSDDB` 为唯一事实来源，统计指定企业范围内、创建日期位于 `[start, end)` 的全部原始状态订单。范围最长 366 天；来源截至时刻、所选日期、企业范围和版本随接口结果返回。

金额用 Decimal 保留 ERP 四位小数。原始数据口径不变；经营看板当前暂按 CNY 和 Asia/Shanghai 展示，有效销售按下面的独立规则派生。不把订单金额命名为支付成交额、平台收入或净 GMV。所有待确认细节集中见 [业务假设台账](business-assumptions.md)。不同角色不共用不同授权范围的快照。

| # | 指标／分析 | 定义与来源 | 边界 |
|---|---|---|---|
| 1 | 销售订单金额 | 每个唯一 `XSDDH.DjLsh` 的 `ZJE` 求和 | 全部原始状态，含已退回状态；不扣退货，不等同支付 |
| 2 | 销售订单数 | 当前范围内唯一 `DjLsh` 数量 | 不是已核验的平台主订单数或商家子订单数 |
| 3 | 下单采购企业数 | 按 `XSDDH.DWBM` 去重 | 仅统计所选期内有订单的企业，不是注册企业数 |
| 4 | 平均订单金额 | 指标 1 ÷ 指标 2，四位小数、ROUND_HALF_UP | 订单数为零时返回 null；不叫支付客单价 |
| 5 | 销售明细行数 | 唯一 `(DjLsh,DjBth)` 数量 | 先验证组合键，不按商品或批次随意去重 |
| 6 | 下单商品种数 | `XSDDB.SPBM` 去重数 | 不自动合并不同商家的标准商品或不同规格 |
| 7 | “订单完成”状态订单数 | `DDZT = '订单完成'` 的订单数 | 仅按原始状态标签统计，不推断已收款 |
| 8 | “订单完成”状态订单金额 | 同上范围 `ZJE` 求和 | 不作为正式有效成交口径 |
| 9 | 每日订单趋势 | 按 `CJRQ` 日期分别计算金额、订单数及企业数 | 全期企业数独立去重，不能累加每日企业数；备份之后日期不补零 |
| 10 | 采购企业排行 | 按 `DWBM` 汇总订单金额和订单数 | 金额降序、编码升序；返回排行总组数和 Top N |
| 11 | 商品排行 | 按 `SPBM` 汇总明细 `JE`，订单 ID 去重计数 | 不能把表头总金额复制到每行；商品订单数不能再相加作为总订单数 |
| 12 | 订单状态分布 | 按 `DDZT` 汇总订单数和表头金额 | 原始标签保留，不擅自映射成支付或履约状态 |
| 13 | 单价数量差异行数 | 比较 `SL × DJ` 与原始 `JE` | 标记质量问题，不重写金额，不阻止已通过主明细对账的结果 |

发布前检查：必需字段、空键、重复键、空金额、浮点转换、日期范围、企业权限范围、孤立明细、无明细订单、逐单主明细对账及 SQL 控制总数／金额。关键检查失败不生成快照；已有快照不被覆盖。

当前证据包含原销售单据 ID、业务单号、企业编码与订单所存名称、日期、状态及商品行 ID、商品编码／名称、原始数量／单价／金额。名称仅供本地页面展示，不参与去重。未读取联系电话、收货地址、证件、银行信息或自由文本备注。

## 暂定有效销售派生口径

`backend/config/business-rules.json` 中的 `qy.operating.v1` 默认纳入订单完成、已出库；排除其他状态。按此范围重新计算相同的订单金额、订单数、企业数、平均金额、趋势和客户／商品排行，所有页面与证据分页共用快照内的同一状态集。未知状态排除并列入 `unknown_statuses`，不静默计入。

原始指标仍以 `qy.sales_orders.v1` 返回。派生结果放在 `operating` 中，保存规则全文、policy_id 和 SHA-256 内容指纹；旧快照的 operating 为空，可继续读取原始指标，但新版看板明确提示需重新生成。修改当前配置不改变已经生成的快照。有效金额加排除金额应等于原始金额，订单数同理。

卡片和排行显示两位小数，证据显示四位；前端用十进制字符串与 BigInt 做显示舍入，汇总和业务计算仍由 pandas／Decimal 完成。SVG 图表仅将金额转换成绘图坐标。

## 网页分析派生指标

网页分析新增的派生指标：等长期间订单金额差额与变化率（零基数为 null），按商品／客户的差额贡献，以及日金额较前日变化至少50%的规则线索。它们继续使用同一快照的有效状态；比较期必须完整覆盖且不重叠。贡献全量计算再取前N项，其他维度增减另列，合计应等于总变化。日波动不代表统计显著性或因果；区间首日不检测。详见 [分析说明](analysis-assistant.md)。

## 暂不启用的指标

支付成交额、成功退款金额、当期支付减退款净额、商家销售额、平台佣金收入、正式复购率及流失判断。原因分别是资金事件、商家归属、收入事实、有效成交口径及足够完整历史尚未验证。

## 合成验收样例

`backend/tests/conftest.py` 使用三个虚构订单：A 企业 100 和 200，B 企业已退回状态订单 90，其中第一个订单有两行 60 和 40。本阶段全部状态的订单金额应为 390、订单数为 3、企业数为 2；“订单完成”状态金额为 300。

这与 AGENT 中“成功支付 300、退款 50、净额 250”的资金事件样例是不同指标。后者保留用于未来支付／退款模块，本阶段未宣称实现该模块。

实现参考：[pandas SQL 读取与 coerce_float](https://pandas.pydata.org/docs/reference/api/pandas.read_sql_query.html)、[SQLAlchemy SQL Server 连接](https://docs.sqlalchemy.org/en/20/dialects/mssql.html)。
