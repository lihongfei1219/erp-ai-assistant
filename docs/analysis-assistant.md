## 启动

日常推荐使用8001，打开网页即可进入，无需本地令牌；服务当前是否运行见[项目进度](project-status.md)。下方脚本默认使用8000；可追加 `--port 8001` 使用README推荐地址。

在项目根目录用uv安装Python依赖并检查环境：

```powershell
uv sync --locked
uv run python scripts/check_environment.py
```

依赖由根目录`pyproject.toml`和`uv.lock`维护，`.python-version`默认3.11。前端首次使用需在`frontend/`执行`npm ci`、`npm run build`。Windows一键入口`Setup-Environment.ps1`仍可使用，内部已改为uv项目命令；npm ci前先关闭前端开发／测试进程。环境检查不连接ERP、不调用模型、不发飞书消息。默认数据快照缺失时须恢复快照或通过`--report-path`指定已有文件；依赖安装不能替代数据准备。

依赖和数据就绪后，从项目根目录运行：

```powershell
uv run python scripts/start_backend.py
```

如果旧后端正在运行，先在其终端按 Ctrl+C，然后重新启动。打开 http://127.0.0.1:8000 ，直接进入「AI 数据分析」。已有项目无需重新取数；服务会加载既有经营快照。更换数据范围仍使用 `workers.analyze_sales` 生成新快照并重启服务。

## 用法

提交自然语言问题后，输入框保留刚才输入的文字，返回结果、补充引导或重试成功均不自动清空，可直接修改后再次提交。“清除追问上下文”仍会清除本轮输入和会话；此保留不包含刷新或关闭页面后的持久保存。

手动分析可直接选择分析类型和日期，不调用外部模型。自然语言使用根目录 `.env` 的已有 `ERP_AI_*` 配置和百炼兼容地址；环境变量优先，`ERP_AI_ENABLED=false` 可关闭。密钥不进入前端。可用完整日期会显示在手动分析区域，备份当日不作为完整一天。

直接用自己的话描述需求即可，不需要完整句式或一次提供所有参数。以下只是使用示例，不是可接受问法清单；实际日期必须在当前快照范围内：

- `统计2026年9月1日至7日销售概览`
- `分析2026年9月1日至5号的销售数据，哪些药品卖的好`
- `2026/9/1到2026/9/5，哪些商品卖得不错，给我列个榜单`
- `2026年9月1日至7日每日销售趋势，并列出商品销售额前5名`
- `2026年9月1日至7日客户订单数排行前10名`
- `比较2026年9月8日至14日与2026年9月1日至7日的销售额，按商品拆解变化贡献`
- `2026年9月1日至7日日波动线索`
- 完成一次分析后输入 `再看客户排行`，继承上次明确的分析日期；「清除追问上下文」取消继承。
- 商品排行后输入 `换成按订单数排，取前5名`，或继续 `取前3名`；同对象追问保留未修改的指标和条数，切换客户／商品对象时重新采用默认值。

“卖得好／卖的好／畅销／受欢迎”默认按销售金额降序展示前10名，无需再次确认。明确指定订单数或前N名时优先使用用户要求。页面「本次问题理解」展示校验后的日期（含结束日）、指标、条数；说明来自实际执行参数，不直接展示模型推测。

“卖得少”等低值表现支持从低到高排行；未指定指标时同样默认有效订单金额。同对象追问可以切换升降序，保留日期、指标与条数；例如先看订单数排行，再问“那卖得少的呢”，继续按订单数升序。排序后才取前N项，同值按编码升序。仅包含所选期间有有效销售记录的对象，不能据此找出所有零销售商品。

用户已确认网页问数中的泛称“药品”按当前商品范围理解，结果显式标注“未按药品类别筛选，可能包含器械、保健品等其他商品”。“只看药品／排除器械／感冒药”等明确分类筛选仍需接入分类数据；销量、件数不能用金额或订单数替代。

自然语言日期支持完整ISO日期区间、中文年月日区间、九月十五号／9月15号等单日和今天／上周／昨天／最近N天；相对日期锚定真实提问日。“这几天卖了多少钱”缺日期时可直接回复“三天”或“九月十五号”。已确定日期会固定在会话中。期间比较需两个等长、不重叠区间；缺比较期时可直接补充比较日期。

页面在输入框下展示已理解的目标、已有条件及其来源（明确指定、沿用、默认）。条件足够就执行；缺关键信息时一次只问一个问题，并提供当前可用的建议。可以选择建议、选择日期，或继续自由输入；点击已有条件会把修改提示放入输入框，补充后提交即可。明确修改或移除条件时保留其余条件，组合问题通过目标ID区分，不因只提到其中一项目标就丢弃其他目标。

正常补充、能力缺口和日期缺口显示引导卡片。比如明确要求件数而当前只有金额和订单数时，会保留件数需求并解释限制，由你决定是否改口径。日期不覆盖时显示实际完整日期，由你选择是否改期；不会把“今天”偷偷换成历史日期。同一疑点反复出现时继续显示草稿和修改入口，不要求重新填写所有内容。

会话过期或快照变更时，页面保留当前可见草稿和未完成补充，停用旧建议。点击「恢复这份草稿」后，才将展示的需求和补充作为新问题重新理解；也可以直接提出新问题。此恢复依赖页面仍保有草稿，不保证关闭或刷新页面后恢复。模型、网络等服务故障单独显示错误并允许重试。

## 对话状态与重试

网页与飞书自由问数默认使用LangGraph编排。条件不足时保存当前草稿并暂停；补充文字或选择建议后继续。服务端重启后，只要仍在30分钟有效期且快照／版本未变，原页面中的会话可以继续；刷新或关闭页面后自动找回草稿尚未实现。

网络中断后的「重试本次请求」沿用请求编号，已完成则返回原结果。模型明确失败时，点击重试才会发起新的调用。旧建议、同一会话并发提交、已过期或范围变化的会话不会直接执行；按页面提示恢复可见草稿或重新提问。模型调用前进程退出的原始输入不会自动恢复。

开发运行：从根目录执行`uv sync --locked`同步`uv.lock`，按原启动方式启动即可，默认引擎为`langgraph`。若需要临时回退，可在启动进程前设置`ERP_ANALYSIS_ENGINE=legacy`；切换后原图会话需显式恢复为新会话。检查点及本地回执位于`.local/langgraph/`，可用`ERP_GRAPH_STATE_DIR`指定目录，网页和飞书自动分开。请将该目录视为本地业务数据保管，不提交Git；模型密钥和业务快照仍沿用原配置。

## 输出与指标

组合分析可继续追加目标，也可只修改其中一项。目标不明确时，助手会保留想修改的内容并先帮助定位；已经说明的日期和指标无需全部重写。一次最多6个目标，互相依赖的目标不会自动拆开执行。

| 分析 | 输出 |
|---|---|
| 概览 | 有效订单金额、订单数、采购企业数、平均订单金额、商品种数 |
| 趋势 | 逐日金额／订单数，覆盖范围内的零销售日，折线图 |
| 客户／商品排行 | 金额或去重订单数可升序／降序，同值编码升序；最多50项，柱状图 |
| 期间比较 | 本期、比较期、增减金额、变化率，以及按商品或客户拆解的贡献；保留未展示维度的增减合计 |
| 日波动 | 相邻完整日金额绝对变化比例达到50%的规则线索；零基数单列，不是统计显著性或因果判断 |

金额计算采用 Decimal，表格及下载保留四位小数。图表仅将金额转换为绘图坐标，鼠标提示保留精确金额。零订单平均金额、零基数变化率返回空值。商品按明细金额统计，客户按订单表头统计；主明细先对账，不能按商品订单数求和得到全期订单数。

每次结果包含来源时间、统计日期、授权范围、规则版本与指纹、分析编号、确定性结论、表格、图表及订单证据。点击「查看证据」可选择对应订单；每行最多100个订单 ID，并保留全部订单数。下载 JSON 包含分析计划与完整返回结果，可本地留档。日波动当前提供当日订单证据；前日基线证据可通过该日概览/趋势查询。

## 当前能力边界

- 数据来自现有销售快照，不代表实时 ERP。日期最多90个完整日，每个计划最多6个步骤。
- 复用令牌绑定的企业范围；当前没有正式 SSO、行级用户权限产品。只在既有内部本地部署范围使用。
- 采用快照内有效状态和指标口径，不能将订单金额解释为支付成交额、净利润或收入。
- 成本、资金事件、地区、类别、供应商等事实仍未接入，也不支持指定客户／商品筛选或预测。库存仅支持备份时点的商品批次余额。
- 模型只理解业务意图，不接收结果、不执行SQL/Python。云端适配器可替换；输入包含当前问题、日期、业务定义、结构化条件与待补充事项，以及服务端裁剪的能力和完整日期元信息。不传原始对话历史、ERP结果、名称目录或身份；能力元信息只含授权范围是否覆盖全平台等布尔边界，不含企业身份。
- 运行时不预设客户问法。模型根据业务定义识别意图，程序校验结构化条件并执行；模型仍可能误解，日期表达也受当前解析器支持范围限制。理解结果会展示实际指标和日期供核对。
- 四域均已接执行器，以当前快照是否包含对应事实为准。退货与销售出库支持概览、趋势、商品／客户排行、明细和有无记录；库存支持单时点概览、商品排行、批次明细和有无库存。退款、退货率、库存历史趋势／周转仍返回能力说明。
- 按地区、仓库或其他维度分析可以自由表达，语义层保留原维度；当前执行器支持商品／客户分组，其他维度显示能力缺口。按地区分组与限定某个地区是不同条件，不能混为一谈；只有明确选择替代建议后才改变维度。
- 当前分析是有界快照上的请求内本地计算，API 将同步计算放在线程池；未建设持久后台分析队列。大范围任务继续由独立快照 CLI 完成。
- 网页分析不增加ERP写入或自动调度；飞书通过独立机器人复用该分析能力，见[飞书问数](feishu-analytics.md)。

## 开发接口与验证

本机分析接口无需访问令牌；数据仍受服务端快照范围和日期限制：

- `GET /api/v1/analysis/catalog`：保留可用日期、工具／指标定义和模型启用状态；新增`capability_version`、`max_items`、`object_filters`。`semantic_domains`由统一能力视图生成，每域包含`executable`、`reason_code`、可用日期、粒度／时间依据及实际支持的操作指标组合。不可执行域的执行清单为空，库存受全平台授权与备份时点限制。模型能力元信息和飞书帮助使用同一来源。
- `POST /api/v1/analysis/converse`：网页引导接口，飞书复用同一个底层对话服务；一次请求完成理解、引导或执行，通常只调用一次模型。
- `POST /api/v1/analysis/run`：`{"steps":[{"kind":"summary","start_date":"2026-09-01","end_date_exclusive":"2026-09-08"}]}`。
- `POST /api/v1/analysis/ask`：`{"question":"2026年9月1日至7日销售概览","previous_plan":null}`。
- `POST /api/v1/analysis/interpret`：同样的输入，只理解与检查可执行性，不计算业务结果；返回`status`、`message`、`semantic`、`conversation_token`。使用当前快照及其数据范围。

新客户端使用`/converse`。新问题发送`{"question":"这几天卖了多少钱"}`；自由补充发送`{"question":"三天","conversation_token":"上轮返回值"}`。HTTP 200的`DialogueTurn.status`有四种：

| status | 含义 |
|---|---|
| `result` | 条件满足，`result`包含原`AnalysisResponse` |
| `needs_input` | 需要补充一个关键条件或消除歧义 |
| `capability_gap` | 已理解，但有业务能力尚未接入 |
| `data_gap` | 日期或数据覆盖不足，需要调整范围 |

每轮还包含`understood_summary`、`draft`、`clarification`、`choices`、`applied_defaults`、`available_dates`、`repeated_clarification`及`conversation_token`；`allow_free_text`始终为true。草稿带稳定目标／条件ID，字段来源区分`explicit`、`inherited`、`default`。

选择建议发送`{"choice_id":"本轮返回的ID","conversation_token":"本轮令牌"}`，不传自行拼出的补丁。日期选择只适用于`action.kind="date_range"`的建议，例如`{"choice_id":"本轮日期建议ID","date_range":{"start":"2026-09-01","end_exclusive":"2026-09-06"},"conversation_token":"本轮令牌"}`。起点包含、终点不含；日期仍检查完整覆盖及90天上限。`question`与`choice_id`互斥。服务端从签名上下文取出允许动作，校验本轮、目标、字段和待解决事项；建议动作不重新调用模型。

`/converse`的失效上下文返回409与`detail.code="context_expired"`；不属于当前轮次的建议返回409与`choice_expired`。参数错误仍为422，模型不可用为503。本机接口无需访问令牌，会话上下文仍使用服务端私有密钥签名。客户端应显示草稿，让用户明确恢复或重新提问，不能剥掉失效会话令牌后静默继续旧动作。

旧接口保持兼容：`/ask`对澄清返回422，`detail`为`{"code":"clarify","message":"...","conversation_token":"..."}`；能力缺失为`unsupported`，日期不覆盖为`data_unavailable`。`/interpret`只做理解检查，对这些语义状态返回200。旧接口签名或上下文失效仍为422，不套用新接口的409约定。

旧`/ask`成功分析仍返回原`AnalysisResponse`及`conversation_token`，`previous_plan`兼容旧客户端；网页自由对话改用`/converse`的签名令牌并支持清除。令牌绑定快照／授权、保留30分钟，不应记录到公共日志。配置、供应商替换和会话边界见[架构说明](erp-ai-assistant-plan.md)。

查询范围不足或条件不明确会引导补充，模型不可用单独提示故障；都不返回伪造零值。模型仍可能误解或超时，需要结合理解摘要核对，并持续做真实供应商评测。Plotly 脚本由 `/assets/analytics-plotly.js` 本机提供；开发模式也已通过 Vite 代理。

离线自动测试使用合成数据。真实模型联调需显式执行：

```powershell
uv run python scripts/probe_analytics_model.py --probe
```

独立语义层的合成云端回归使用`uv run python scripts/probe_semantic_model.py --probe`；可加`--case combined`等只复测指定用例。该脚本覆盖四域、口语日期、组合、筛选与澄清补全，不读取ERP、不发送飞书消息。旧脚本保留用于旧计划器回归。

四域执行器的连续对话联调使用：

```powershell
uv run python scripts/probe_operations_model.py --probe --flow all
```

`--flow smoke`只验证三个新增业务域；`--flow dialogue`验证组合后修改单项、追加独立日期的库存目标、当前库存的数据缺口与明确选择快照、自由补日期、客户维度追问及不支持指标保留整个组合。`--flow inventory`仅复测当前库存→接受快照→再问当前库存的3步流程。`--flow recovery`验证退货／出库比较能力缺口，再明确选择概览、排行或明细的8项流程。`all`共21项检查，核对业务域、操作、指标、每项目标日期及结果域；库存既有`stock`／`quantity`按同口径验证。前置步骤失败时后续记为跳过并返回非零退出码，不把跳过计为通过。该入口仅构造合成报告，不加载真实快照，问题不进入运行提示词或问法词典。

该命令只发送合成问题，验证工具选择、日期、条数及不支持请求的澄清，不读取 ERP。验证结果见 [记录](validation.md)。

## 自然语言标注评测

统一入口为`scripts/evaluate_dialogue.py`，用例在`backend/evaluation/cases.json`，运行逻辑位于独立的`backend/evaluation/`。线上语义服务不导入这些样例。当前27个场景、36轮对话：14个来自用户截图中的通用原句，13个是明确标记的合成补充场景；不包含客户身份、真实商品名称或业务明细。这是种子验收集，不代表完整真实流量分布。

从项目根目录执行：

```powershell
uv run python scripts/evaluate_dialogue.py --output .local/evaluations/replay.json
uv run python scripts/evaluate_dialogue.py --cloud --case screenshot_chinese_date --case multi_domain_edit_append --output .local/evaluations/cloud.json
```

输出文件必须是新文件。`--case`可重复指定；省略时运行整套。默认回放`replay`中的参考语义，通过真实对话、编译器和执行器校验链路，**不衡量大模型理解准确率**。`--cloud`忽略参考语义，把问题和结构化上下文交给当前供应商；不读取ERP或本地真实快照、不发送飞书消息，不需要启动网页服务。两种模式均固定使用合成四域报告及2026-09-22作为提问日，避免“今天”随运行日期漂移。

每轮校验全部目标及已标注字段、筛选条件、规范化日期、引导状态和关键待补字段；执行结果还核对完整计划及结果业务域。目标顺序不影响判断，增加或丢失目标会失败。库存`stock/quantity`按等价口径核对；未指定的非关键指标可以不标注。“有退货吗”等只问存在性且未要求指标的场景可以显式设置`ignore_plan_metric`，此选项仅适用于未标指标的明细／存在性计划，不能用于排行或明确指标请求。“哪个最好”的唯一对象限制仍必须标为`limit=1`。

评测还按业务配置核对尚未填入的默认指标，排行的空对象与程序默认商品等价；显式非默认指标、地区对象和数量限制仍严格检查。单轮可人工标注最多3个`alternatives`，每个备选都须给出完整验收条件。例如对象未说清的退货列举，先问对象或先问日期均可有合理路径；无论走哪条路径，后续明确商品和日期后都必须执行列举，不能变成总金额。报告通过`accepted_variant`标明匹配主标签0或某个备选，不根据模型输出自动放宽标签。

前置轮次失败后，依赖轮次记为跳过，整场景失败并返回退出码1；参数或配置错误返回非零。报告记录场景通过率、各轮通过／失败／跳过、引导轮数、重复澄清、无必要引导、意图偏差及P50/P95耗时。平均引导轮数以全部选择的场景为分母，失败后跳过的轮次不计入已发生引导；报告中的错误类型用于区分供应商故障和评测内部错误。通过率衡量符合标注预期，正确解释能力缺口也算通过，不等同于所有问题都能计算结果。

报告仅保存用例ID、状态、枚举类型、失败字段、计数和耗时，不保存问题正文、筛选值、模型原始响应、结果明细或凭据。实际澄清字段、标准对象、筛选字段与操作符用于定位偏差，开放名称统一显示other。模型标识、语义配置／提示词／用例集SHA256用于对比版本。新增样例需先脱敏并标明来源，分别审查参考语义与预期结果；默认pytest同时回放整个用例集。截图中尚未确认含义的表达需要先评审标注，不能为了凑通过率随意选定指标。
