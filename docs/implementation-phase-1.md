# 第一阶段实施安排

日期：2026-09-16。依据：主方案第 6、11、15 节，以及本地 QY 备份的实际表结构。

本文件保留第一阶段范围；后续已增加可配置暂定规则和 React 看板，见 [业务假设台账](business-assumptions.md) 与 [看板验证记录](phase-2-validation.md)。其中“暂不实现前端”仅描述当时交付边界，当前状态以 README 为准。

本阶段交付可运行的销售订单分析纵向流程：只读 SQL Server 取数 → 独立命令行进程执行 pandas → 保存本地开发快照 → FastAPI 查询结果与订单依据。先把金额和关联关系验证清楚，再接支付、AI 和经营提醒。

## 已确定的实现范围

1. 可重跑的元数据导出、系统字段字典和数据质量检查脚本。
2. 数据源映射、13 项首批指标定义及明确的待确认事项。
3. Python 3.11、FastAPI、pandas、SQLAlchemy、pyodbc 的项目基础与锁定依赖。
4. 以销售订单创建日期取数，统计全部状态的订单金额、订单数、采购企业数、平均订单金额，以及每日趋势、客户和商品排行、状态分布。
5. 独立命令行进程生成不可覆盖的结果快照；保留来源、范围、生成时间、指标版本、对账结果及订单证据。
6. API 只读取完成的快照。开发令牌绑定单个结果快照，前端不能通过传企业 ID 改变范围。真实多用户身份体系尚未建设。
7. 合成数据单元和 API 测试，以及显式开启的本地 SQL Server 只读集成测试。

## 数据发现对规划的影响

- `XSDDH` 是销售订单表头，`XSDDB` 是表体；不是已经验证的平台主订单／供应商子订单模型。
- `XSDDH.ZJE` 与按 `DjLsh` 汇总的 `XSDDB.JE` 在整个备份中逐单一致。
- 客户按 `DWBM` 关联 `HGGOUHDWDAH.DWBM`，商品按 `SPBM` 关联 `HGJYSPDAH.SPBM`；不能把 `DWBH`、`SPBH` 当成档案表的 `DjLsh`。
- `DKJE` 全部为零，`YWSKH` 数据时间与当前订单不重合，不能发布“支付成交额”或把零值理解成未收款。
- `XSTHDH` 是退货单；退货不是成功退款事件，本阶段不扣减订单金额。
- 数据所有者已确认备份覆盖平台全部商家；商家归属映射、有效成交状态、币种／时区和历史变更水位仍需确认。

## 本阶段技术决策

开发快照先保存到被 Git 忽略的 `.local/reports/`，采用完整写入后原子发布的方式；这是用于核对备份的阶段性工具，不代表主方案中的助手 SQL Server 库、增量同步和持久化任务调度已经实现。每次从指定日期及企业范围重新读取，不通过最大 ID 推测增量。

源数据库不创建表、不改数据、不启用 CDC。首次摸底使用现有 Windows 身份；正式部署仍需 DBA 提供对象范围受限的只读账号。程序只提供固定的 SELECT 查询，不接受模型或 HTTP 传入 SQL。

暂不实现模型调用和前端业务页面。FastAPI 的本地接口文档提供可操作的查询入口；前端技术形态确定后再接页面。后台计算由独立 CLI 执行，API 不执行 pandas 长计算。

## 完成门槛

- 真实数据库连接与 Decimal 读取通过；读取范围有上限，日期／企业参数化。
- 合成样例覆盖一对多关联、重复键、缺字段、零结果、日期边界、金额精度及权限范围。
- 同一次读取中的订单总额、逐单明细总额与独立 SQL 汇总一致；差异会阻止发布。
- API 未授权不能读取快照，不能选择另一快照或企业范围，返回的数据含口径与时间。
- README、开发约定和方案状态同步更新，明确尚未实现项。
